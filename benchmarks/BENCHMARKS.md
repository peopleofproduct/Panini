# Panini Benchmarks

Public, reproducible accuracy receipts — the numbers below are generated by `benchmarks/run.mjs` against compiled `dist` builds, not hand-edited.

## What is measured

| Section                    | What it proves                                                                                                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Extraction accuracy**    | For every supported CSV layout, 5 seeded statements × 40 transactions each are generated with ground truth (`@paniniapi/simulator`), then re-parsed. Every field must match — 100% or it's a real regression. |
| **Anomaly safety**         | Corrupted statements (bad dates, missing amounts, short rows) must never crash the extractor or fabricate more transactions than exist.                                                                       |
| **Narration intelligence** | The shipped narration corpus (`packages/rules-engine/rules/corpus`) is scored against expected channel/counterparty/type fields — the same gate as `corpus.test.ts`, reported as percentages.                 |
| **Insights determinism**   | `analyzeTransactions` on a seeded statement must return byte-identical reports across runs — the core "replayable" guarantee.                                                                                 |

## Reproduce

```bash
npm ci && npm run build
npm run bench        # writes results/latest.json + this file's results block
npm run bench:ci     # exits 1 on any regression — used in CI
```

Determinism: all inputs are seeded (`mulberry32`), so identical commits produce identical numbers. Machine-independent.

## Thresholds (CI gate)

- **100%** exact field match (date, amount, direction, balance) on every clean generated row
- **0** crashes or over-extractions on corrupted statements
- **0** corpus sample failures
- Insights output **byte-identical** across runs
